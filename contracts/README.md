# contracts/

Everything the UI project needs to talk to the Barkfield Road Admin API. Copy this whole folder into
the UI repo; it is written to travel.

| File | What it is |
|---|---|
| **`openapi.json`** | The machine contract. Generate your client types from it |
| **`API-CONTEXT.md`** | How the API behaves — auth, errors, conventions. Read first |
| **`PAGES.md`** | Every screen and the endpoints feeding it, with the domain vocabulary |
| **`UI-KICKOFF.md`** | A brief to paste into Claude Code in the UI workspace |
| **`regenerate.ps1`** | Refreshes `openapi.json` (and the stats block in `API-CONTEXT.md`) from the running API |
| **`audit.cjs`** | Checks the markdown still matches the spec |

## Reading order

1. **`API-CONTEXT.md`** — 10 minutes, and it prevents the three mistakes that cost a day each.
2. **`PAGES.md`** §0–1 for the shell, then whichever section you are building.
3. `openapi.json` only through your generator. It is 380 KB; nobody reads it.

## Refreshing the contract

Run from the **API** repo whenever a controller signature or a DTO changes:

```powershell
./contracts/regenerate.ps1
```

It starts the API in Development, fetches `/openapi/v1.json`, writes the file, updates the generated
stats block in `API-CONTEXT.md`, and stops the API. Then copy `openapi.json` to the UI repo and
regenerate your types — the diff is the change you need to react to.

Two things it gets deliberately right and should not be "simplified":

- It writes with `WriteAllText` and an explicit no-BOM encoding. Windows PowerShell 5.1's
  `Set-Content -Encoding utf8` adds a byte-order mark, and a BOM makes this file unparseable by
  `JSON.parse` and by most client generators — which is the only thing it exists for.
- The JWT secret it sets is a local throwaway. The app refuses to start without one, and the process
  is killed as soon as the document is fetched.

## What is custom in the document

Three extensions, added because the default document left them out. Each replaced something that
would otherwise have been hand-maintained in prose and gone stale:

| Extension | Why |
|---|---|
| `x-required-permission` | Which permission guards each operation, read from the `[RequirePermission]` attributes. Gate UI controls on this, not on a table you type out |
| `x-anonymous` | The five endpoints needing no token, so the client does not wait for sign-in before calling them |
| `x-enum-names` / `x-enum-varnames` | Enums cross the wire as integers; without this a client sees `status: number` |

There is also a bearer security scheme, which ASP.NET Core does not infer on its own — without it the
document described every endpoint as anonymous and a generated client would have sent no token.

## Keeping the docs honest

Both markdown files make factual claims about the API — endpoint paths, permission strings, counts.
`audit.cjs` checks them against `openapi.json`:

```bash
node contracts/audit.cjs
```

It verifies that every `/api/...` path the docs cite exists, that every permission string they name is
one some endpoint actually requires, and that no path count typed into a sentence has gone stale. It
exits non-zero on a problem, so it can go in a pre-commit hook or a CI step.

Worth running after any endpoint change. The numbers in `API-CONTEXT.md` §1 are generated by
`regenerate.ps1`, so those cannot drift — this catches the prose that can.
